# Project Architecture Rules

- Drive all homepage scroll motion and reading progress from one passive scroll listener writing CSS variables/styles, with IntersectionObserver for reveals; reduced motion and small screens get a static stacked layout, and interactive examples remain usable without animation.
- Lazy-load the homepage Three.js scene and read its progress from the existing scroll listener; dispose GPU resources and retain readable static content when WebGL or motion is unavailable.
- The code understander runs the sdev-written engine (`lang/agent/understander.sdev`, via `src/lang/agent/sdev-engine.ts`) first and uses its answer only when it is sure of every line and the result parses; the TypeScript understander remains the fallback — so behaviour migrates rule by rule without regressions.
- New language primitives needed by sdev-written tooling are added to both the JS builtins and the Python interpreter in the same change — dual-runtime parity is required.
- The understander sets `board "<id>"` blocks aside from its sdev rules and reads them with the hardware reader (`src/lang/hardware/understand.ts`, wired in `src/lang/agent/boards.ts`): lines the transpiler already knows stay byte-identical, loose lines become the hardware language, and only lines no rule can place go to the AI — so firmware is helped without ever being rewritten as sdev. `stripBoardBlocks` and the linters use the same block finder, so unclosed blocks are never read as sdev.
- `sdev:ai` files (first code line `!#ai`) are translated to canonical sdev by `lang/agent/ai-dialect.sdev` inside the agent's `begin()`, so every runtime and the rest of the understander only ever see canonical sdev.
- Working code reaches the compiler exactly as written (`asWritten()`): real sdev keywords and called runtime functions are never "non-canonical", a v1 file that parses with every name defined is left byte-identical, v2 files are compiled as written before the understander reads them, and a failing reading falls back to the author's file — AI `reconsider` runs only when the file needed reading. `npm run test:understander-docs` gates this against every documented example.
- The understander's AI brain runs on the user's computer with nothing to install: a WebGPU model inside the browser (`src/lang/agent/browser-brain.ts`, WebLLM) first, then a user-configured model server (the CLI's local option); the website edge function only when the file says `!#agent:online` or the user enables it — so everyday use costs no workspace AI credits. The local prompt (`src/lang/agent/brain-prompt.ts`) mirrors the edge function's and must be kept in sync.
- `release.json` holds the single version for the IDE, CLI, VS Code extension and desktop app; `node scripts/release.mjs` rebuilds the CLI from `src/lang`, ships that same CLI inside the extension, writes `public/downloads/*` and `public/releases.json` — every installed tool reads `releases.json` to update itself, so never bump a tool's version by hand.
- Every server-side AI call goes through `supabase/functions/_shared/ai.ts` (`aiUrl`/`aiHeaders`/`aiModel`/`aiKey`), which uses the project's own OpenAI-compatible provider when `SDEV_AI_API_KEY` is set and only falls back to the legacy hosted gateway otherwise — so the platform can leave Lovable without touching each function.
- Systems/causal-AI libraries (`lang/stdlib/v2/bits|mem|oce.sdev`) are pure SDEV v2 built only from existing VM ops, so they run unchanged on the seed VM and the native backend; classic and `!#ai` files get the same functions as built-ins ported line for line in `src/lang/builtins/oce.ts` and `public/sdev-interpreter.py`, gated by `scripts/test-oce-parity.ts` (identical output everywhere) — change all three together.
- The self-hosted v2 compiler has no error channel, so `bin/sdevhost.mjs` and `runWasm` check every program with the reference compiler first and report unknown functions, wrong argument counts and list `+` without the list library; v2 `a + b` compiles to `list_concat_two` when either side is a list literal, in the self-hosted, reference and native compilers alike.
- Keep the SDK-generated MCP function self-contained; give the generator a relative alias for its Windows entry path so it cannot emit a machine-local npm import that blocks publishing.
- Load unrelated pages and optional IDE tools only when selected, with panel-local Suspense boundaries; opening the editor must not wait for homepage assets, hardware tools or execution engines. Live diagnostics share `lintSdev.ts` and load the existing hardware reader only for board candidates; offline library storage lives in `library-cache.ts` without dialect-engine dependencies. Gate startup dependencies and diagnostic parity with `test:ide-loading`.
